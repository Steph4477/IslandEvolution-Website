# Dépannage

Commencer par reproduire le symptôme, relever le premier message exact et noter le dernier changement. Utiliser `git status --short --branch` et `git diff` pour voir le travail en cours. Les commandes ci-dessous sont à lancer depuis `IslandEvolution-Website`.

| Symptôme                                                      | Causes possibles                                                                             | Vérifications                                                                                                 | Correction                                                                                                                                                  | Validation                                                                                                          |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Vite ne démarre pas                                           | Dossier incorrect, dépendances absentes, version Node ou port                                | Vérifier `package.json`, `node --version` et la sortie du terminal                                            | Depuis la racine et sous Node 24, lancer `npm ci` puis `npm run dev`. Utiliser l’URL annoncée par Vite                                                      | Charger l’accueil et vérifier la console                                                                            |
| Erreur TypeScript                                             | Type incorrect, import ou valeur éventuellement absente                                      | `npm run check`, ouvrir le premier emplacement signalé                                                        | Corriger le type, le chemin ou traiter la valeur absente. Reprendre la forme des appels existants                                                           | Relancer `npm run check` et le test concerné                                                                        |
| Erreur Svelte                                                 | Syntaxe de balisage, binding ou props incompatibles                                          | Lire l’erreur du terminal et contrôler le composant puis son appelant                                         | Corriger la balise ou la prop dans sa zone de responsabilité                                                                                                | Refaire l’action dans le navigateur et relancer `check`                                                             |
| Le build échoue                                               | Erreur de compilation, route prérendue ou URL publique incorrecte                            | Comparer `npm run build` et `npm run publish:pages -- --check-only`                                           | Corriger la première cause. Pour Pages, suivre les exigences de `VITE_SITE_URL` du [guide de déploiement](DEPLOIEMENT.md)                                   | Relancer les deux builds et contrôler le sitemap de production                                                      |
| Une image est absente                                         | Casse, chemin, fichier oublié ou préfixe Pages                                               | Repérer la requête dans **Réseau** et comparer au chemin sous `static/`                                       | Corriger le chemin et utiliser `asset(...)` dans le composant                                                                                               | Recharger en développement et vérifier le chemin sous `/IslandEvolution-Website/` dans le build                     |
| Moko ou l’intro semble bloqué                                 | Mouvement réduit, état de défilement, clip absent ou erreur dans le navigateur               | Contrôler la préférence de mouvement, `data-clip`, la console et l’entrée du clip dans `src/lib/moko/`        | Corriger la ressource ou la transition isolée. Conserver les seuils et la chronologie si le comportement attendu est déjà couvert                           | Rejouer l’intro, son saut, le défilement et les compétences sur les deux tailles d’écran                            |
| Une traduction manque ou reste dans l’autre langue            | Clé asymétrique, paramètre `lang` ou préférence mémorisée                                    | Contrôler les deux entrées de texte et l’attribut `<html lang>` dans **Éléments**                             | Compléter la clé correspondante dans la source et relier le libellé à `copy`                                                                                | Tester les deux boutons, une navigation légale et un rechargement                                                   |
| Un bouton déborde ou devient difficile à atteindre sur mobile | Largeur fixe, zone interactive recouverte ou état de la caméra                               | Tester autour de 393 px avec affichage mobile et vérifier le point cliqué dans **Éléments**                   | Ajuster la règle CSS ciblée dans le composant après comparaison avec le bureau                                                                              | Tester les boutons, la modale et le défilement avec une largeur étroite. Confirmer sur Android physique si possible |
| Le bouton bêta ne lance pas la messagerie                     | Champ ou case invalide, fenêtre fermée aux candidatures ou gestionnaire `mailto:` absent     | Lire le message dans la modale, vérifier les deux cases et la présence d’un client mail dans le système       | Corriger la saisie ou la configuration du client. Suivre le [guide du formulaire](FORMULAIRE_BETA.md)                                                       | Exécuter les tests bêta. Sur un environnement de démonstration, vérifier le brouillon sans l’envoyer                |
| Une adresse est refusée                                       | Extension absente, espaces internes, caractères de contrôle ou limite dépassée               | Tester un exemple réservé tel que `demo@example.org`, puis comparer à `test@gmail`                            | Corriger la saisie. Si la règle est en cause, ajuster uniquement après validation métier                                                                    | `node --test tests/beta-application.test.mjs`, puis contrôle de la modale FR/EN                                     |
| Une vidéo reste sur l’affiche                                 | Consentement refusé, mouvement réduit, lecteur hors écran ou requête bloquée                 | Regarder l’état des préférences, **Réseau** et la console                                                     | Autoriser YouTube pour ce test et essayer le bouton de lecture. Contrôler le retrait dans un second temps                                                   | Vérifier que rien ne part vers YouTube avant accord et que le lecteur disparaît après retrait                       |
| Git indique des fichiers inattendus ou une divergence         | Édition locale, index déjà préparé ou branche distante avancée                               | `git status --short --branch`, `git diff`, `git diff --cached`, `git log --oneline -6`                        | Identifier l’auteur des modifications et traiter les fichiers concernés. Résoudre la divergence en préservant les commits                                   | Vérifier le contenu du prochain commit et l’état du dépôt                                                           |
| Pages ne se met pas à jour                                    | Build incomplet, authentification, concurrence sur `gh-pages`, échec de déploiement ou cache | Lire la sortie du script, comparer les deux branches distantes et vérifier le workflow Pages pour le bon hash | Suivre le [guide de déploiement](DEPLOIEMENT.md). Après une avance concurrente, reprendre à partir de la branche distante actuelle avec la commande normale | Confirmer le succès GitHub Pages et charger les nouveaux fichiers à l’URL publique                                  |
